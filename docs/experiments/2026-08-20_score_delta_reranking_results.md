# 分数增速二次排序实验结果

> 日期：2026-08-20
> 策略：v75m（v75j + score_delta二次排序）
> 状态：❌ 证伪，保留代码备用

---

## 1. 实验假设

在v75j的打分排序基础上，先选出top 20候选股，再用"分数增速"（当日分数 vs N日前分数的变化量）做二次排序，看能否选出短期表现更好的股票。

**逻辑**：分数高的股票是"好股票"，分数增速快的股票是"正在变好的股票"，短期可能"正在变好"的比"已经很好但停滞"的更有爆发力。

## 2. 实现方案

### 核心模块
- `scripts/strategies/score_delta.py` — 分数保存/读取/增速计算/二次排序
- `scripts/strategies/v75m_score_delta.py` — v75m策略实现

### 工作流程
1. 每日选股时，先按v75j因子算综合分数
2. 调用`save_scores()`保存当日分数（DB或内存缓存）
3. 调用`get_historical_scores()`获取N日前分数
4. 计算delta = 当日分数 - N日前分数
5. 在top 20候选股中，按delta降序重排
6. 选出最终持仓

### 参数
- `SCORE_DELTA_LOOKBACK`：回看天数（1日或5日）
- `SCORE_DELTA_TOP_M`：二次排序范围（默认20）

## 4. 技术实现细节

### 内存缓存模式
WF回测时，`score_delta.py`使用内存缓存（`_score_cache`字典）而非DB存储历史分数。原因：
- WF模式下`SKIP_DB_WRITE=True`，不写入DB
- 内存缓存在每个fold开始时清空，保证不跨fold泄露信息

### DB表结构
```sql
CREATE TABLE strategy_scores (
    strategy_name TEXT,
    date TEXT,
    code TEXT,
    score REAL,
    PRIMARY KEY (strategy_name, date, code)
);
```

## 5. 失败原因分析

1. **分数本身噪音大**：每日打分受短期波动影响，增速更多是随机波动
2. **二次排序破坏一次排序**：v75j的综合因子排序已经很好，二次排序引入噪音
3. **1日和5日无差异**：说明分数变化在短期内没有持续性信号

## 6. 结论与建议

- **分数增速方向放弃**：实证表明打分的短期变化没有预测能力
- **保留代码**：`score_delta.py`和`v75m_score_delta.py`保留，可作为未来研究参考
- **如果要做动量加速度**：建议用原始价格/成交量信号（如5日涨幅的加速度），而非打分的加速度
