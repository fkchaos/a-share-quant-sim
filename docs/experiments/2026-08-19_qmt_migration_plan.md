# QMT实盘迁移计划

**日期**: 2026-08-19
**目标**: 将v61c/v75j策略从模拟盘迁移到迅投QMT实盘

---

## 一、迁移风险清单

### 🔴 高风险（必须解决才能上实盘）

| # | 风险点 | 描述 | 应对方案 | 状态 |
|---|--------|------|---------|------|
| H1 | 数据一致性 | QMT行情源 vs 腾讯API，close/volume可能有差异 | 上线前用QMT数据重跑IC，对比模拟盘 | ⏳ |
| H2 | 策略逻辑验证 | 换仓信号、打分逻辑在QMT环境能否正确执行 | QMT模拟盘跑1-2周，对比信号一致性 | ⏳ |
| H3 | 成本估算偏差 | 滑点、佣金、印花税在实盘的真实影响 | 用历史数据加 realistic 成本回测 | ⏳ |
| H4 | 涨跌停处理 | 涨停买不进/跌停卖不出，模拟盘可能没考虑 | 策略增加涨跌停过滤逻辑 | ⏳ |
| H5 | ST/退市风险 | 持仓中出现ST或退市股 | 增加ST检测，触发时强制卖出 | ⏳ |

### 🟡 中风险（上线后持续监控）

| # | 风险点 | 描述 | 应对方案 |
|---|--------|------|---------|
| M1 | 订单执行延迟 | QMT下单到成交的时间差 | 用限价单，避免市价单 |
| M2 | 资金利用率 | 10万本金，单票仓位控制 | 保持≤10只持仓，单票≤15% |
| M3 | 网络/系统故障 | QMT断线、服务器宕机 | 设置止损单，保留手动干预能力 |
| M4 | 策略衰减 | 实盘环境vs回测环境差异导致alpha衰减 | 每月复盘，IC持续监控 |

### 🟢 低风险（已验证/可接受）

| # | 风险点 | 说明 |
|---|--------|------|
| L1 | 策略逻辑本身 | v61c/v75j已在模拟盘验证，WF Sharpe>1.9 |
| L2 | 资金规模 | 10万规模对流动性无压力 |

## 二、迁移验证流程

```
Phase 1: 数据验证 (1-2天)
  ├── QMT导出1个月日线数据 vs 腾讯API数据
  ├── 对比close/volume/amount差异
  └── 重算IC，确认因子有效性一致

Phase 2: 信号验证 (3-5天)
  ├── QMT模拟盘跑v61c/v75j
  ├── 每日对比：QMT信号 vs 我们的信号
  ├── 记录不一致的日期和原因
  └── 信号一致率>95%方可进入Phase 3

Phase 3: 小资金实盘 (1-2周)
  ├── 投入1-2万试水
  ├── 记录每笔成交的实际滑点
  ├── 对比实际收益 vs 模拟收益
  └── 滑点<0.3%方可进入Phase 4

Phase 4: 全量切换 (持续)
  ├── 切换全部10万资金
  ├── 每日监控持仓和收益
  ├── 每周复盘策略表现
  └── 发现异常立即暂停
```

## 三、分时数据新机会分析

### QMT能拿到什么数据

| 数据类型 | 粒度 | 用途 |
|---------|------|------|
| Tick数据 | 逐笔成交 | 主力行为分析、大单追踪 |
| 分时K线 | 1分/5分/15分/30分/60分 | 日内趋势、突破 |
| 逐笔委托 | Level2盘口 | 封单结构、买卖压力 |
| 资金流向 | 主力/散户 | 资金面因子 |
| 集合竞价 | 开盘/收盘竞价 | 开盘预测、尾盘信号 |

### 可能的新alpha方向

**① 日内动量/反转（高优先级）**
- 1分钟/5分钟级别的动量反转
- 日内涨跌幅与次日收益的关系
- 尾盘30分钟信号（对次日开盘有预测力）
- **实施难度**: 低（因子计算简单）
- **预期alpha**: 中等（IC 0.02-0.05）

**② 开盘/收盘竞价策略（中优先级）**
- 集合竞价量价特征
- 开盘价偏离度（vs 昨收）
- 尾盘异动检测
- **实施难度**: 低
- **预期alpha**: 中等

**③ 分时成交量结构（中优先级）**
- 大单占比变化
- 主力净流入趋势
- 量价背离检测
- **实施难度**: 中（需要Level2数据）
- **预期alpha**: 中等

**④ 日内波动率模式（低优先级）**
- 日内波动率聚类
- 高频波动率因子
- **实施难度**: 高
- **预期alpha**: 不确定

### ⚠️ 不建议的方向

| 方向 | 原因 |
|------|------|
| 高频交易（秒级） | 10万本金不支持，交易成本吃掉alpha |
| 复杂ML模型 | A股截面ML已验证无效（v30/v47教训） |
| 过度拟合日内模式 | 日内数据噪声大，容易过拟合 |

### 分时数据应对策略

**短期（上QMT前）：**
1. 不改策略逻辑，先验证日线策略在QMT的执行一致性
2. 分时数据先**只记录不交易**，积累数据

**中期（上QMT后1-2月）：**
3. 用分时数据构建新因子，在模拟盘验证IC
4. 优先测试：尾盘信号、开盘竞价、大单流向
5. 通过验证的因子加入v61c/v75j作为辅助信号

**长期（3月+）：**
6. 如果分时因子有效，考虑独立的日内策略（v84系列）
7. 日线策略+日内策略组合运行
